title: RealMap 1.0.1 — clearer when the game does not answer

**Update both the app and the mod** (Mod Hub, or `realmap-mod-1.0.1.zip`), then restart the game.

## Fixes
- **"The game does not answer" on game build 40423 and later**: since that update the game only lets mods read and write a few of its folders, and the one RealMap used is no longer one of them, so the mod never saw the app's requests. The app and the mod now exchange their files in the `towns_industries` folder (files named `realmap_…`, they also show in the Map Editor's Towns / Industries import list: leave them there).
- The mod no longer compares its clock with the app's to accept a request. A request sent while the Map Editor is still loading is now sent again automatically.
- **Explicit causes**: when the game does not answer, the app now says why: the mod gives no sign of life (game closed, mod not enabled or out of date), the mod runs in another game folder (another Steam account), the game is not in the Map Editor, another map is still being generated, the mod and the app versions differ.
- **Game log**: the mod writes every step it takes (loaded, watching, request accepted or left aside and why, files it cannot save) in the game's `crash_dump/stdout.txt`. If the game still does not answer, the app tells you where that file is: send it with your report.
- The app picks first the game folder where the RealMap mod last ran.
- **Game version**: the Export tab shows a discreet note when the game is a build RealMap was not tested with (tested: 40423, 40425).

## Installation
Same as 1.0.0: see the [README](https://github.com/Spit8/RealMap#readme). Installed apps update themselves from the Export tab.
