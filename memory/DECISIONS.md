# Durable Decisions

Record decisions that future work should preserve unless new evidence or an explicit user request justifies revisiting them.

## DECISION-001 — Open data sources
- Status: ACTIVE · Date: 2026-10-29
- Decision: **OpenStreetMap** (ODbL) for all vector data (roads, rails, water, forest/landuse, places + `population`); **Copernicus DEM GLO-30** for relief worldwide, **IGN RGE ALTI 1 m/5 m** as high-quality option for France. Overpass for prototyping, Geofabrik `.osm.pbf` later.
- Rationale: only free worldwide source covering every feature TF3 needs; GLO-30 is the cleanest free global DEM; IGN is close to the game's 4 m grid.
- Alternatives: SRTM (holes, <60°N), Overture Maps (no relief, nothing decisive).
- Revisit if: licence or availability changes.

## DECISION-002 — Tauri app + thin mod, HQminiMap stack
- Status: ACTIVE · Date: 2026-10-29 (user choice)
- Decision: external desktop app **Tauri 2 + SvelteKit SPA + Svelte 5 + TS + OpenLayers** (same as HQminiMap HQ-001/HQ-002), heavy processing in TS workers; the mod stays thin.
- Rationale: map UI to select the area, writes directly into `<UD>`, distributable; reuses proven code (`detect_paths`, Lua writers, fast-png workers).
- Alternatives: pure web (cannot write game folders), Python CLI (no map UI).

## DECISION-004 — Regional scale and water handling (v0.2)
- Status: ACTIVE · Date: 2026-10-29 (user feedback: "marchotte", sea level -4, regional scale wanted)
- Decision:
  - Map picked by the game's own size + format (`mapsizes.ts`), never "tiles".
  - Horizontal `scale` = real m per game m (default 1:3); vertical scale default 1/√scale (user choice), editable.
  - Relief: IGN RGE ALTI in France (DTM, exact grid), Copernicus elsewhere / to fill gaps, averaged over the sample footprint.
  - TF3 has one global water level (0): sea = no data or ≤ 0.5 m connected to the edge; OSM lakes / rivers carved to −depth; reference height (game 0) = sea level, else 5th percentile of the water's real height, else lowest point; land ≥ +1 m; banks limited to slope 0.4; lakes needing > 30 m of trench stay land. Water Level stays 0 in the Map Editor.
  - Preview: 2D hill-shaded image (user choice) overlaid on the OSM map, computed on a ≤ 640 px grid.
- Revisit if: in-game import shows the rivers mask or biome defaults behave differently (QUESTION-002/006).

- Decision:

  - Preview: « Carte » / « Aperçu » tabs; `PreviewView` (game-metre OpenLayers view, towns with moves, hover readout, legend, stats) shared with a detachable Tauri window (`preview`, route /preview, prerendered) fed by Tauri events (`preview:hello|request|data|status`). Updated on click only. Preview grid 1 024 px.

All are settings.

## DECISION-008 — Two phases, realistic water, repaired river network, automatic sizes, industries (v0.6)
- Status: ACTIVE · Date: 2026-10-30 (user feedback after testing v0.5 in game: shallow rivers, flat sea, steep banks, preview broken, rivers ending nowhere, sizes should apply without a click, add industries; « voir l'application en 2 phases »)
- Decision:
  - Phase 1 « Données réelles » (`fetchData`, cached per area: relief, sea floor, WorldCover, OSM water / places / industrial sites, summary in the panel, raw layers on the map) and phase 2 « Transformation » (worker, re-run automatically ~0.7 s after a setting changes), then « Export ».
  - Water: depth profile from the shore (1 m + 0.35 m per m, rivers 10 m, lakes 8 m), sea from EMODnet / ETOPO capped at 40 m (FACT-018), gentle river banks 0.15 within 200 m (sea / lakes 0.4), valley lowering renamed `valleySlope`.
  - River network (`rivers.ts`): dangling mouths joined to water within 100 game m, else routed downhill (priority-flood on a ≤ 768 grid) to water or the map edge; sources kept but tapered over 500 m. OSM direction = flow, overridden when the start is ≥ 5 m lower.
  - Sizes: the mod's mod-area button pump applies them in the Map Editor (once per import, only when ≥ half the towns match by name); the button stays as a fallback. The editor's own import is kept (user's choice).
  - Industries (`industries.ts`, FACT-019): real OSM sites first (clustered 2 km, ≤ quota/10 per type), land-cover primaries (farm ≥ 50 % crops, livestock ≥ 40 % grass, forest ≥ 60 % trees, fishing offshore), production chains completed from the economy, quota ≈ tiles / 40, placed on valid ground (900 m from towns, 1 200 m apart) or open water; manual picks like towns. (Selection and quota superseded by DECISION-009.)

## DECISION-009 — Left panel in 3 tabs, map-only result, finished rivers, game quotas (v0.7)
- Status: ACTIVE · Date: 2026-10-30 (user feedback on v0.6; user choices: selection settings live with the lists in « Export », the detached preview window is removed)
- Decision:
  - UI: panel on the left, tabs « Zone et données réelles » / « Transformation » / « Export »; the « Aperçu » tab, `PreviewView` and the detached window are gone (legend and height readout moved onto `AreaMap`). Map: double click moves the centre, click opens a sheet, right click adds / removes, option to hide what is not chosen.
  - Projection: local transverse Mercator centred on the area (FACT-022); IGN requested in UTM and resampled.
  - Water: river cross-section scaled to the local width (middle always `riverDepth`), shore 0.5 m / land 0.5 m with easing across the waterline, mouths carried into still water and the sea dug to river depth near them, channels between water pieces ≤ `waterJoinM` (64 game m) apart when one holds a river and both are ≥ `minLakeHa` (first try without the size rule meshed the Marais Poitevin ditches: 686 channels → 1), `riverMinWidth` enforced everywhere (tapers, thin OSM areas), WorldCover wetland ≥ 5 ha → lakes 4 m deep. Settings version 7 resets `landMin` to 0.5.
  - Towns and industries: additive selection — the automatic choice ignores manual picks, so adding one adds one and removing one leaves a gap. Towns: indicative game limit ≈ 41 per 3 136 tiles. Industries: count from the game's density (FACT-021), chosen by whole chains, each chain scored by its industry most present in reality (OSM sites 3–4 + 2·log2 n, land cover 1–3) minus 0.25 per extra industry; list sorted by that presence, broken chains flagged. Water industries only with open water ≥ 300 m from the shore (Lyon's lakes made a sand excavator / oil platform get chosen then silently dropped), else the economy's land fallback.

## DECISION-010 — Leaner UI with a log, Ctrl placement, game-like rivers, names, start network (v0.8)
- Status: ACTIVE · Date: 2026-10-31 (user feedback on v0.7; user choices: minimum river width 64 m, roads = town pairs chosen from the real network but routed by the game)
- Decision:
  - UI: no static explanation text in the panel (field tooltips only; the explanations live in `ARCHITECTURE.md` « Réglages »). Statistics, data summary, town report and the technical journal go to one log panel at the bottom of the left panel (`LogPanel.svelte`, `importer.events`, levels info / warn / error / debug, « Détails » shows debug). Phase 1 shows its steps with state and detail (`importer.dataSteps`).
  - Map: Ctrl held shows a ghost of the area under the mouse, Ctrl + click moves it; double click zooms again. Symbols never decluttered (`declutterMode: "none"`), only names. Towns listed and drawn: chosen + not placed + the 10 most populous others (`shownTownKeys`); others are added through a search field (accent-insensitive).
  - Rivers: `riverMinWidth` 64, `riverDepth` 9, the game's cross-section shape (`riverDepth·(d/32 m)^0.8`, FACT-023) and the middle of every river at full depth (2026-10-31, user: « l'eau des rivières profonde, berges douces » — full depth at 32 m instead of the game's 48 m: steeper submerged slope ~0.3 m/m, land banks unchanged at 0.15); shore easing on the first water row only; `underwaterSlope` 0.5, mouths dug over 300 m. Settings version 8 migrates the old defaults. No beach output (FACT-023).
  - Industries: whole footprint off water (radius per type + 30 m, slope checked under it, FACT-024); names = OSM name, else « <industrie> de/d'/du/des <ville la plus proche> »; written in the note for the mod (`industries = {{tag, x, y, name}}`).
  - Heights: Minimum / Maximum are whole metres (floor / ceil) and the heightmap is stretched over that range.
  - Network (`core/network.ts`): third Overpass query (motorway…secondary, railway main / branch, `out body geom`); graph by shared OSM nodes; each town linked to 1–2 others by cheapest real road not passing within 600 m of a third town (a lone town gets its cheapest link), each town to ≤ 1 industry within 6 km of road, links removed by hand never replaced; railway = longest main-line path resampled every 250 m inside the map (a 2nd only if it serves ≥ 3 towns). Note fields `connections`, `industryLinks`, `rail.lines` for the mod, which has the game build them (mod part in its own session).

## DECISION-012 — Whole generation automatic in the Map Editor, launched by the app (v0.9)
- Status: ACTIVE · Date: 2026-10-31 (user: no button, the Tauri app launches the generation; the mod only checks it is in the Map Editor; order heightmap > biomes > towns > industries > roads > rail; user accepted that the game links every industry while building roads, so the « 0–1 industry per town » rule and DECISION-011's order are dropped)
- Decision:
  - Protocol by userdata files (the game cannot be called from outside, `core/gamelink.ts`): the app writes the PNGs, `towns_industries/<n>.lua` (towns), the note `importcity/<n>.lua` (+ `heightmap`, `biomes = {biomes, mountains, rivers}`, `economy`, whole-metre `minHeight` / `maxHeight`, `tiles`), then `importcity/request.lua = { id = ms, name, createdAt }`; the mod answers in `importcity/status.lua = { id, stage, message, failed, report }`. The app follows it every second (`importer.watchGame`): stages shown under « Générer la carte », report in the log; no answer in 15 s → « Le jeu ne répond pas : … éditeur de cartes, nouvelle carte vide <taille>, mod importcity » ; 5 min without news → error.
  - Mod: the mod-area pump (every 30 ticks) runs each new request (`importcity_auto.lua`): checks (Map Editor, map size = note `tiles`, map empty, files listed by `app.getAllHeightmaps` / `getAllBiomes`, import generator of the climate, towns file) with explicit errors, then heightmap and biomes through the game's own `MapPreviewComp` hosted in a progress window (FACT-025) + `makeWorldReplaceTerrainCmd`, towns (`createTowns` + `makeTownCreateCmd`, then real sizes), industries (named), roads (`makeTownConnectWithIndustriesCmd(…, keep=false)`), railway (refusals with `makeProposalData(...).errorState`). A request runs once (status with its id) and only if younger than 20 s. The window has no button any more.
  - `core/network.ts` plans town pairs and railway only (industry links removed).

## DECISION-014 — Railway designed in the app, laid right after the terrain; export reuses phase 1 (v0.11)
- Status: ACTIVE · Date: 2026-10-31 (user, after v0.10 in game: line discontinuous, no minimum curve, through towns, broken at water / roads / towns; choices: rail before towns, industries and roads; no station; « Générer la carte » must not redo the data retrieval)
- Decision:
  - `core/railway.ts` `designRail`: the OSM main line (`network.ts` `mainRail`, every 50 m) is only a guide. Town zones (250 m + ½ capacity, ≤ 900 m; overlapping zones merged into their enclosing circle; a zone > 1500 m — a conurbation — or holding an end of the line is crossed) crossed once along the shorter arc of their circle (stretch from first to last point inside replaced; during the smoothing a point back inside goes radially out — the first version pushed points along the line's local normal, which flips as the line bends: with a user-sized selection on Lyon the line wound round Caluire, 102 km and 100 000 self-crossings instead of 21 km and 0); curves opened up to `minRadiusM` (default 300 m); detours capped at 2× the guide length (the unmerged version ran out of memory on Lyon's 67 towns). Profile = ground smoothed over ±200 m, |grade| ≤ `maxGrade` (default 2.5 %), deck ≥ 8 m over water. Bridge where wet or > 10 m above ground, tunnel where > 15 m below, runs < 100 m dropped; open water > 1.5 km splits the line. Nodes every ~100 m `{x, y, z, tx, ty, tz, kind}` (unit 3D tangent, kind of the next edge n / b / t) in the note's `rail.lines`. Settings « Voie ferrée » (Transformation tab), in `optionsKey`. Industries keep their footprint + 50 m off the track.
  - Mod order heightmap > biomes > **rail** > towns > industries > roads (`GAME_STAGES`, `importcity_auto.lua`). `B.line` lays the app's nodes as is: tangents = unit × edge length, BRIDGE (stone) / TUNNEL (`tunnel_a`, `tunnel_b` from 1970) / NORMAL; refused chunk → edge by edge → a refused track edge once as a bridge → skipped, its position listed in the report (« coupures vers … »). No stations.
  - Export (`importer.run` → `fullInputs`): phase-1 data reused; only IGN at full resolution, Copernicus tiles if missing and WorldCover at the fine level are loaded; its own steps (relief, cover, compute, files) before the game ones; phase-1 steps untouched.

## DECISION-015 — Town needs, cheaper rail profile, beaches, deeper rivers, lighter panel (v0.12)
- Status: ACTIVE · Date: 2026-10-31 (user feedback on v0.11: no commercial / industrial districts creating demand; very high and long viaduct at Lyon; panel too busy, lists in a separate consultable view; trees on beaches; rivers still shallow, keep gentle banks. Choices: needs coherent with the placed industries, district sizes from OSM, lists in a panel over the map)
- Decision:
  - Rail profile (`core/railway.ts` `profile`): dynamic programming over 0.25 m height levels, hard |grade| ≤ max and deck ≥ 8 m over water, cost = cut / fill (h²) ≪ bridge (> 10 m) / tunnel (< −15 m), bridges over 30 m priced as a last resort. The old two-pass clamp kept the line's first height (a long viaduct going down, a tunnel going up, depending on the line's direction). The « Pente max. » setting is now the real grade, converted with `gameGrade` (× scale × verticalScale, ≤ 0.08). Lyon 1:3 e2e: 21.1 km, 12 bridges, highest 26 m, 2 tunnels, game grade ≤ 4.0 %.
  - Rivers (`core/terrain.ts`): `riverDepth` 9 → 14 m (saved 9 migrated, settings v9), `RIVER_BED_M` 32 → 20 m with a straight slope, waterline easing no longer applied to river cells (except on grids coarser than 20 m). Land banks unchanged (`riverBankSlope`). Lyon e2e: mean depth over every river cell 10.4 m at the 16 m preview grid.
  - Land use (`core/landuse.ts`, phase-1 step « Plages et zones d'activité »): one Overpass query, beaches / sand / dunes with geometry, `landuse=commercial|retail|industrial` as bounds only (`out bb`). Beaches: OSM beach cells, or WorldCover 60 / 20 / 100 within 150 m of sea / lake and ≤ 5 m, become OPEN (biome 1) in the worker (`clearBeaches`, count in the log).
  - Town shares: commerce / industry area (bbox × 0.6) within `townLandRadiusM` against WorldCover built-up area, relative to the map's mean, scales the game's usual 30 % / 20 %; each 10–45 %, housing ≥ 40 %; no business area → 50 / 30 / 20.
  - Town needs (`core/townneeds.ts`): only the town goods whose whole chain is placed (FACT-029 categories), round robin, fewest goods first then far from the producer (< 2 km last), 1–3 per land use by capacity × share. Sent in the note's `towns[i].shares` / `needs`; the mod's `split` uses the shares and `setNeeds` sends `makeTownUpdateCargoNeedsCmd(entity, {res kept, com, ind}, true)` after the size update. Shown in the town sheet.
  - Panel: every block is a folding `Section` (open state kept per id), secondary transformation blocks folded by default; town / industry / road-rail lists moved to `ui/ListsPanel.svelte` over the map (« Listes » button, « Voir les listes » in Export), a click on a name centres the map beside the panel and opens the sheet (`AreaMap.focus`); `toggleLink` moved into `importer`.
- Checked: 107 unit tests, check, build, Node e2e Lyon, lupa simulation (shares + needs command), browser UI with an injected result. NOT TESTED in the Tauri app or in game.

## DECISION-018 — Roads in manual mode, the mod lays the drawn roads, industry roads, orange #FD9401 (v0.15)
- Status: SUPERSEDED by DECISION-019 (roads laid by the mod and industry roads removed; manual mode and orange kept) · Date: 2026-10-31 (user, after v0.14: deleting a road brought new links to nearby towns; in game the roads did not follow the map, e.g. no road between the Microbrasserie Caribrew and Givors; choices: « Tracé de la carte », and « tout manuel » with a reset button named « Appliquer les paramètres par défaut » that asks for confirmation)
- Decision:
  - Manual roads: settings v11 `roadsFrozen` (null = automatic).
